# GHoT × Static Live — WORSHIP-STAGE-001

**State:** research-grade, opt-in, **offline rehearsal preflight**. No real church connected. No open LAN worker, Tithely account, Suno session or stream keys involved.

## What GHoT adds

GHoT does not author the song, approve theology, or play the backing tracks. It acts as an available *body* that can be asked to inspect a local copy of a Static Live stage package under a strictly owner-configured directory.

```text
Congregational seeds → Living Hymnal (human review)
  → approved song → Static Live stage projection
                                   ↓
                            GHoT offers
                       worship.stage.preflight
                                   ↓
              local designated package: projection.json
                                   ↓
                   read-only PCM WAV header checks
                                   ↓
                       GHoT task/receipt
                                   ↓
              rehearsal readiness report, NOT playback
```

One GHoT worker can prepare a package. Another GHoT node without access to the audio should **not** be offered or assigned the task. GHoT uses its ordinary external adapter manifest; no new privileged GHoT core API or remote shell is introduced.

### Verify offline, with synthetic WAV files

From the GHoT repository root:

```sh
python3 examples/worship-stage-001/sim.py
```

The simulation configures its own temporary package, runs the **real** GHoT `reference_node.execute` path and checks the resulting task and receipt. It deliberately forces sample-rate/duration errors, an unplayable Static Live projection, invalid packet IDs, a symlink escape, and absent owner configuration. Nothing is uploaded.

### Try with a *synthetic or authorized* local rehearsal package

A package directory looks like:

```text
<owner-configured-root>/
  sunday-001/
    projection.json     # generated by Static Live; not a new song
    stems/
      pad.wav
      click.wav
```

Start from an already compiled `static-live.stage-projection/v0.1`, with the referenced WAVs underneath the same named package directory. This is owner-controlled local file preparation; the adapter will never download material itself.

Opt in for **local execution only**:

```sh
export GHOT_WORSHIP_PACK_ROOT=/absolute/path/to/authorized-rehearsal-packages
export GHOT_ADAPTER_MANIFESTS="$(pwd)/examples/worship-stage-001/adapter-manifest.json"
python3 ghot/reference_node.py probe
python3 ghot/reference_node.py run worship.stage.preflight '{"packet":"sunday-001"}'
```

The output `ghot.receipt.status = ok` says the *preflight calculation completed*, even if `output.result.ready_for_rehearsal_review = false`. Check the readiness value and errors; an execution receipt is not approval to play on Sunday.

The adapter accepts only an owner-provisioned **packet ID**, not a path. The root must be set beforehand by the machine owner. File paths are taken only from the pre-existing Static Live projection under that root, with traversal/symlinks blocked. Output intentionally omits original song titles, lyrics, filenames and absolute paths.

### Limits and safety

- Current standard-library Python `wave` preflight supports common **PCM WAV** 16/24/32-bit mono/stereo. Other valid DAW formats, especially 32-bit floating point, may be rejected until a separate bounded media decoder is implemented. This is not the same WAV parser as Static Live's Node preflight; use its full native preflight as well.
- Checks declared Static Live `playable`, click location, WAV readout, sample-rate and duration consistency. It cannot prove the audio is synchronized at the first sample, correctly gain-staged, legally licensed, routed to the hardware, or safe for livestream use.
- The generic GHoT LAN `/task` service is **not an authenticated church service**. If this adapter is opt-in enabled, an untrusted LAN requester could potentially invoke the bounded preflight and learn availability or timing metadata. **Do not expose the GHoT LAN task port to untrusted devices or public internet**, and do not enable the manifest for actual congregational data without an approved local trust/access design.
- GHoT currently cannot carry local WAV bytes between machines merely by selecting a capability. Packaging/copying audio to worker storage is a separate permissioned transport problem, and is not implemented here.
- GHoT is expressly forbidden from taking over the stage: no live channel control, no FOH output, no livestream credentials, no click routing hardware, and no autonomous Sunday cues.
- For real congregational use, church leadership must approve the arrangement and distribution, and credentials/contributor permissions must be secured separately.

The ultimate live audio and video functions remain with church-operated, deterministic playback systems and people.

**EXECUTION != READINESS.** **REHEARSAL PREFLIGHT != SUNDAY SHOW CONTROL.**
